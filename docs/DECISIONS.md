# Decisions

Append-only. To change a decision, add a new dated entry that supersedes the old one and mark the old one *Superseded by D-xxx*. Don't silently edit or delete entries.

Status: **Proposed** (awaiting approval) · **Accepted** · **Superseded** · **Open** (needs a decision before a stated point)

D-001 – D-017 were proposed and accepted on 2026-10-02.

---

### D-001 — Native SwiftUI for the iPhone app · 2026-10-02 · Accepted
Developing from Windows does not change the target. Cross-platform frameworks (React Native, Flutter, PWA) were rejected: the Share Extension, SwiftData, local notifications and later WidgetKit are all first-class in native iOS, and the screenshot-capture experience is the product's core.

### D-002 — Single repo, no monorepo tooling · 2026-10-02 · Accepted
`apps/ios`, `apps/display`, `supabase/`, `docs/`. No Nx/Turborepo/workspaces — the two apps share no build tooling.
Deviation from the brief: `supabase/` at the root instead of `backend/supabase/`, because the Supabase CLI expects `./supabase` by default and there's no other backend.

### D-003 — Xcode project generated by XcodeGen, not committed · 2026-10-02 · Accepted
`apps/ios/project.yml` is the source of truth; `WantWise.xcodeproj` is git-ignored and generated on the Mac with `xcodegen generate`. Hand-editing `.pbxproj` from WSL is error-prone and Xcode-only state would be lost between rented Mac sessions. Cost: one `brew install xcodegen` per Mac.

### D-004 — Domain logic in a Foundation-only Swift package · 2026-10-02 · Accepted
`WantWiseCore` holds transitions, date/countdown rules, metrics and the capture inbox format. It imports Foundation only, so it builds and tests on Linux (WSL). This maximises what can be verified without a Mac.

### D-005 — SwiftData local-first, thin `WantStore` for writes · 2026-10-02 · Accepted
Views read with `@Query`; all mutations go through one `WantStore` class so sync (M3) has a single hook. No per-entity repository protocols or DI framework.

### D-006 — Store only real states; derive "ready to reconsider" · 2026-10-02 · Accepted
Stored: `captured`, `waiting`, `stillWant`, `purchased`, `noLongerWant`. `readyToReconsider` = waiting and `revisitAt` ≤ now; `waitingLonger` = waiting with a wait-longer decision in history; `considering` folded into `captured`. Avoids background jobs flipping state and keeps iPhone and Display consistent.

### D-007 — Decisions are an append-only history table · 2026-10-02 · Accepted
`WantDecision` rows are never edited or deleted. Satisfies "preserve history" and makes sync conflict-free for decisions. `Want.decidedAt/decisionReason` are kept as a convenience copy of the latest decision.

### D-008 — Share Extension completes capture itself and writes to an App Group inbox · 2026-10-02 · Accepted
Apple provides no supported way for a Share Extension to open its containing app, so the extension must finish the whole "Want this?" flow. It writes `<uuid>.jpg` + `<uuid>.json` into an App Group inbox; the app imports idempotently on foreground. Chosen over writing directly into a shared SwiftData store to keep SwiftData out of the memory-limited extension and avoid two-process store writes / dual migrations.

### D-009 — Images as downsampled files, not database blobs · 2026-10-02 · Accepted (location amended by D-019)
Max 2048 px JPEG in the App Group `Images/` directory, referenced by filename. Maps directly to Supabase Storage paths later.

### D-010 — Money as integer minor units · 2026-10-02 · Accepted
`priceMinor: Int` + ISO currency code. Exact across Swift, TypeScript and Postgres.

### D-011 — Display V1 layout: Featured + rail · 2026-10-02 · Accepted
One large rotating hero Want plus a rail of the rest. Chosen over grid (cluttered at distance), carousel (hides items) and full-screen rotation (hides the list). Other scenes (Ready, Decisions, Reflection, Things I Love) come later.

### D-012 — Display: Next.js + plain CSS, fixture data source first · 2026-10-02 · Accepted
App Router, TypeScript, plain CSS, minimal deps. Data behind a `DisplayDataSource` interface with a fixture implementation, so the Display is built in WSL in parallel with iOS work and connected to Supabase in M4. Refresh by 60 s polling, not Realtime.

### D-013 — Sync: client UUIDs, last-writer-wins per Want, server cursor · 2026-10-02 · Accepted
Device-generated UUIDs are primary keys everywhere. Wants use LWW on device `updatedAt`; the pull cursor uses server-assigned `server_updated_at`. Soft deletes. Every table carries `family_id` for RLS. Revisit if a parent device starts editing Wants.

### D-014 — iPhone delivery via TestFlight · 2026-10-02 · Accepted (account ownership superseded by D-018)
A rented cloud Mac can't be cabled to the child's iPhone, and free signing expires in 7 days. Paid Developer Program + TestFlight is the delivery path. GitHub Actions macOS CI for builds is a later option to reduce Mac rentals.

### D-015 — Deployment target iOS 18 · 2026-10-02 · Accepted (provisional; see D-021)
SwiftData matured in iOS 18. Lower only if the child's phone can't run it.

### D-016 — No AI, local notifications only, in V1 · 2026-10-02 · Accepted
Prove the behavioural loop first. Screenshots are stored as-is without OCR. Reminders use `UNUserNotificationCenter` local notifications, reconciled on every launch.

### D-017 — Parent signs in on the child's phone; no child account · 2026-10-02 · Accepted
For M3, the child's iPhone uses a family session established by the parent. `family_members.role` leaves room for `child` and read-only `display` roles later.

### D-018 — Apple signing and distribution via a friend's Developer account · 2026-10-02 · Accepted
The project owner is not enrolling in the Apple Developer Program yet. A friend with an active account will register identifiers, sign builds and distribute through TestFlight from a clone of the **public** repo. So:
- No Team ID, signing identity or provisioning profile goes into the repo. Team-specific values live in a git-ignored `apps/ios/Config/Signing.local.xcconfig` (template committed as `Signing.local.xcconfig.example`).
- Bundle IDs and the App Group are build settings with placeholder defaults, not literals in code.
- The friend's App Store Connect account owns the app record, builds and tester list.
- Instructions for the friend: `docs/APPLE_HANDOFF.md`.
Long-term implications (bundle ID ownership, transfer, data continuity) are recorded in APPLE_HANDOFF.md → "Ownership implications" and must be read before identifiers are registered.

### D-019 — App Group used only for the capture inbox · 2026-10-02 · Accepted
Amends D-009/CAPTURE.md. The SwiftData store and `Images/` live in the **app's own container**, not the App Group container. The App Group holds only `Inbox/` (extension → app handoff). Reason: if the app ever moves to a different team, the App Group ID must change; anything stored in the App Group container would be stranded. Keeping long-lived data out of it minimises what depends on a team-registered identifier. A future widget that needs images can get a copy written to the group at that time.

### D-020 — Default currency CAD, always explicit on each Want · 2026-10-02 · Accepted
`ChildProfile.defaultCurrency = "CAD"` seeds new Wants. Every Want stores its own `currency`. Nothing formats or sums money without the currency code; metrics group totals by currency.

### D-021 — Deployment target: iOS 18 provisionally; iOS 17 is feasible · 2026-10-02 · Open (decide before first Xcode build)
Milestone 1–2 code depends on **no iOS-18-only API**. iOS-18-only features we deliberately avoid: SwiftData `#Index`/`#Unique` macros, SwiftData History API, custom data stores, `@Previewable`, `MeshGradient`. iOS 18's benefit is SwiftData stability fixes (predicate and relationship bugs in 17.0–17.x), and we already reduce that risk by storing enums as raw strings and keeping relationships simple. Supporting iOS 17 would mean a Simulator test pass on an iOS 17 runtime and nothing else. **Decide based on the child's iPhone iOS version.** Not changed automatically.

### D-022 — Proposed identifier namespace `tech.wantwise` · 2026-10-02 · Open (confirm with the friend's account before first signed build)
Placeholders: app `tech.wantwise.app`, share extension `tech.wantwise.app.share`, App Group `group.tech.wantwise.app`. Defined once in `apps/ios/Config/Base.xcconfig` and overridable in `Signing.local.xcconfig`. Nothing is registered yet. Bundle IDs don't require owning the matching domain, but they must be globally unique and the namespace may already be registered by someone else.
